## 1. Diagnóstico da feature atual

### Estrutura
A feature está organizada em 10 sub-telas + arquivos de infra:

| Pasta | Tela | Status |
|---|---|---|
| `01-Login` | LPLoginScreen | ✅ Completa |
| `02-Home` | LPHomeScreen | ✅ Completa |
| `03-Redeem` | LPRedeemScreen | ✅ Completa |
| `04-SendPoints` | LPSendPointsScreen | ✅ Completa |
| `05-Statement` | LPStatementScreen | ✅ Completa |
| `06-Profile` | LPProfileScreen | ✅ Completa |
| `07-PromoDetail` | LPPromoDetailScreen | ✅ Completa |
| `08-Catalog` | LPCatalogScreen | ⚠️ Stub ("coming soon") |
| `09-RewardDetail` | LPRewardDetailScreen | ✅ Completa |
| `10-EarnPoints` | LPEarnPointsScreen | ✅ Completa |
| `Components/` | Componentes compartilhados | ⚠️ Vazio |

### Problemas identificados

#### P1 — `08-Catalog` é um stub incompleto
`LPCatalogScreen` exibe apenas `"lp.catalog.coming_soon"` sem ViewModel, sem dados, sem filtragem. É a única tela sem implementação real.

#### P2 — `Components/` está vazio
Três telas (`LPHomeScreen`, `LPPromoDetailScreen`, `LPRewardDetailScreen`) têm sub-views complexas inlined (4–6 `@ViewBuilder` privados cada). O agente builder indica que views com 3+ sub-views devem usar `Components/` — essa regra não foi aplicada.

#### P3 — Duplicação de `appendTransaction` em 3 ViewModels
`LPSendPointsViewModel`, `LPRewardDetailViewModel` e `LPEarnPointsViewModel` copiam exatamente o mesmo método `appendTransaction(_:)`. Violação do DRY que deve ser extraída para `Services.swift` ou `LPAPIService`.

#### P4 — Membership Tier hardcoded com apenas 2 tiers
`LPHomeViewModel.membershipTier` suporta apenas Bronze → Silver. `LPConstants.Membership` tem apenas `pointsToSilver`. A lógica de tiers está inline no ViewModel em vez de estar em um serviço.

#### P5 — `LPEarnOpportunity` definida dentro do ViewModel
`struct LPEarnOpportunity` está em `LPEarnPointsViewModel.swift`. Deveria estar em `LPModels.swift` junto com os outros modelos de domínio.

#### P6 — Validação de CPF sem algoritmo real
`LPLoginViewModel` e `LPSendPointsViewModel` validam CPF apenas por comprimento (11 dígitos). Não há validação do dígito verificador. Isso é inconsistente com um programa de fidelidade real.

#### P7 — `LPCatalogScreen` sem ViewModel próprio nem testes
Além do stub, não existe `LPCatalogViewModel.swift` nem testes para a tela 08.

#### P8 — Teste de `LPRewardDetailViewModel` não cobre o fluxo `redeem()`
`LPRewardDetailViewModelTests` não testa se o saldo é debitado e a transação registrada após `redeem()`. Cobertura parcial.

## 4. Restrições do agente (do `.github/agents/ios-ds-feature-builder.agent.md`)

- Todos os componentes de UI **devem** vir de `ZodiakiOS/Shared/DesignSystem/`
- **Nunca** hardcodar cores — usar `ZodiakColors.*`
- **Nunca** hardcodar espaçamento — usar `ZodiakSpacing.*`
- Funções sem retorno: `func reset()` (sem `-> Void`)
- Raiz das telas: `ZodiakActivityTemplate`
- ViewModels: `final class + ObservableObject + @Published`
- Localização obrigatória em `en` e `pt-BR` para **todas** as chaves novas
- Rodar `swiftlint lint --fix` após criar/modificar cada arquivo
- Novos arquivos em `Resources/` são incluídos automaticamente no bundle (sem edição de `.xcodeproj`)
